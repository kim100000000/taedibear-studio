## 🔴 Phase 2 — 배포 전, Meta 없이 가능한 것

### 2-1. 결제 연동 + 플랜 제한 (최우선)

> 수익화 핵심. 배포 후에 추가하면 기존 유저 대상 유료 전환이 훨씬 어려워짐.

**백엔드:**
- Free 플랜: 당월 업로드 10회 제한 (인터셉터로 구현)
- 초과 시 403 응답
- 토스페이먼츠 결제 연동 (월 29,000원 정기결제)
- payments 테이블 신규 생성
- API 추가:
  - `POST /api/payments/confirm`
  - `GET /api/payments/status`
  - `POST /api/payments/cancel`
  - `GET /api/users/me/usage` → { plan, used, limit, reset_at }

**프론트엔드:**
- 대시보드에 "이번 달 X / 10회 사용" 카드
- /settings 구독 관리 섹션
- 한도 초과 시 Pro 업그레이드 유도 모달

---

### 2-2. 예약 실패 이메일 알림

> 사용자 신뢰도 직결. 예약해두고 실패했는데 모르면 최악.

- SendGrid 또는 Nodemailer 연동
- 예약 업로드 실패 시 이메일 발송
- 3회 재시도 후 최종 실패 시에만 발송
- 이메일 내용: 실패한 게시물 썸네일 + 재시도 링크

---

### 2-3. AI 캡션 입력 고도화

> 백엔드 추가 없음. Gemini 프롬프트 수정만으로 품질 향상.

- 캡션 생성 시 추가 입력 필드:
  - 오늘의 특별 메뉴 (선택)
  - 이벤트/프로모션 내용 (선택)
  - 강조하고 싶은 키워드 (선택)
- 입력값을 Gemini 프롬프트에 반영
- users 테이블에 업종/분위기 저장 → 이후 자동 반영

---

### 2-4. 랜딩 페이지 완성

> 배포하면 처음 보는 화면. 가입 전환율에 직결.

- 히어로 섹션: 핵심 문구 + CTA "무료로 시작하기"
- 3단계 설명 (업로드 → AI 캡션 → 자동 업로드)
- 요금제 카드 (Free vs Pro 비교)
- 실제 사용 화면 스크린샷/데모
- 푸터: 이용약관, 개인정보처리방침

---

### 2-5. 에러 핸들링 + 로딩 상태 전체 점검

- 모든 API 호출에 로딩 스피너 확인
- 네트워크 오류 시 사용자 안내 메시지
- 빈 상태 화면 (히스토리 없을 때, 예약 없을 때)
- 401 만료 시 자동 로그아웃 + 안내

---

### 2-6. 배포 환경 설정

- 환경변수 dev/prod 분리 (.env.development / .env.production)
- CORS 운영 도메인 설정
- Vercel 프론트엔드 배포 설정
- Railway 백엔드 배포 설정
- 도메인 연결 (선택)
