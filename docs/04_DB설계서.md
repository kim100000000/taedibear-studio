# Taedibear Studio — DB 설계서

**버전:** v1.0  
**작성일:** 2026-06-27  
**DBMS:** MySQL 8.0

---

## 1. 테이블 목록

| 테이블명 | 설명 |
|---------|------|
| `users` | 사용자 계정 |
| `instagram_accounts` | 연동된 인스타그램 계정 |

## 2. 테이블 관계 (ERD 요약)

```
users 1 ──── N instagram_accounts
users 1 ──── N posts
instagram_accounts 1 ──── N posts
posts 1 ──── 0/1 scheduled_posts
```

## 3. 테이블 상세

### 3.1 users

사용자 계정 정보를 저장합니다. 이메일 로그인과 소셜 로그인을 모두 지원합니다.

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 사용자 고유 ID |
| `name` | VARCHAR(100) | NOT NULL | 사용자 이름 |
| `email` | VARCHAR(255) | UNIQUE, NOT NULL | 이메일 (로그인 ID) |
| `password_hash` | VARCHAR(255) | NULL 허용 | bcrypt 암호화된 비밀번호 (소셜 로그인 시 NULL) |
| `google_id` | VARCHAR(100) | NULL 허용 | 구글 소셜 로그인 ID |
| `kakao_id` | VARCHAR(100) | NULL 허용 | 카카오 소셜 로그인 ID |
| `naver_id` | VARCHAR(100) | NULL 허용 | 네이버 소셜 로그인 ID |
| `plan` | ENUM | DEFAULT 'free' | 플랜 (free / pro) |
| `created_at` | TIMESTAMP | DEFAULT NOW() | 가입일 |
| `updated_at` | TIMESTAMP | ON UPDATE NOW() | 최종 수정일 |

```sql
CREATE TABLE users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255),
  google_id VARCHAR(100),
  kakao_id VARCHAR(100),
  naver_id VARCHAR(100),
  plan ENUM('free', 'pro') DEFAULT 'free',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

### 3.2 instagram_accounts

연동된 인스타그램 계정 정보를 저장합니다. 한 사용자가 여러 계정을 연동할 수 있습니다.

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 계정 고유 ID |
| `user_id` | INT | FK → users.id | 소유자 사용자 ID |
| `instagram_user_id` | VARCHAR(100) | NOT NULL | 인스타 고유 ID |
| `username` | VARCHAR(100) | | 인스타 계정명 (@) |
| `access_token` | TEXT | NOT NULL | Meta API 액세스 토큰 |
| `token_expires_at` | TIMESTAMP | | 토큰 만료 시간 |
| `connected_at` | TIMESTAMP | DEFAULT NOW() | 연동 일시 |

```sql
CREATE TABLE instagram_accounts (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id INT NOT NULL,
  instagram_user_id VARCHAR(100) NOT NULL,
  username VARCHAR(100),
  access_token TEXT NOT NULL,
  token_expires_at TIMESTAMP,
  connected_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

### 3.3 posts

게시물 정보를 저장합니다. AI가 생성한 캡션과 실제 업로드 상태를 관리합니다.

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 게시물 고유 ID |
| `user_id` | INT | FK → users.id | 작성자 ID |
| `instagram_account_id` | INT | FK → instagram_accounts.id | 업로드할 인스타 계정 |
| `image_url` | TEXT | NOT NULL | S3 이미지 URL |
| `caption` | TEXT | | 캡션 내용 |
| `hashtags` | TEXT | | 해시태그 (쉼표 구분) |
| `status` | ENUM | DEFAULT 'draft' | 상태 (draft / scheduled / posted / failed) |
| `instagram_post_id` | VARCHAR(100) | NULL 허용 | 인스타 게시물 ID (업로드 후) |
| `posted_at` | TIMESTAMP | NULL 허용 | 실제 업로드 시간 |
| `created_at` | TIMESTAMP | DEFAULT NOW() | 생성일 |

**status 값 설명:**

| 값 | 설명 |
|----|------|
| `draft` | 작성 중 (아직 업로드 안 됨) |
| `scheduled` | 예약 완료 (자동 업로드 대기 중) |
| `posted` | 인스타그램 업로드 완료 |
| `failed` | 업로드 실패 |

```sql
CREATE TABLE posts (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id INT NOT NULL,
  instagram_account_id INT NOT NULL,
  image_url TEXT NOT NULL,
  caption TEXT,
  hashtags TEXT,
  status ENUM('draft', 'scheduled', 'posted', 'failed') DEFAULT 'draft',
  instagram_post_id VARCHAR(100),
  posted_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (instagram_account_id) REFERENCES instagram_accounts(id)
);
```

### 3.4 scheduled_posts

예약 업로드 정보를 저장합니다. cron job이 주기적으로 조회하여 자동 업로드를 실행합니다.

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 예약 고유 ID |
| `post_id` | INT | FK → posts.id | 연결된 게시물 ID |
| `scheduled_at` | TIMESTAMP | NOT NULL | 예약 업로드 시간 |
| `status` | ENUM | DEFAULT 'pending' | 상태 (pending / done / failed) |
| `retry_count` | INT | DEFAULT 0 | 재시도 횟수 (최대 3회) |
| `created_at` | TIMESTAMP | DEFAULT NOW() | 예약 생성일 |

```sql
CREATE TABLE scheduled_posts (
  id INT AUTO_INCREMENT PRIMARY KEY,
  post_id INT NOT NULL,
  scheduled_at TIMESTAMP NOT NULL,
  status ENUM('pending', 'done', 'failed') DEFAULT 'pending',
  retry_count INT DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (post_id) REFERENCES posts(id) ON DELETE CASCADE
);
```

## 4. 인덱스 설계

성능 최적화를 위해 자주 조회되는 컬럼에 인덱스를 추가합니다.

```sql
-- 이메일 조회 (로그인 시)
CREATE INDEX idx_users_email ON users(email);

-- 소셜 로그인 조회
CREATE INDEX idx_users_google_id ON users(google_id);
CREATE INDEX idx_users_kakao_id ON users(kakao_id);
CREATE INDEX idx_users_naver_id ON users(naver_id);

-- 사용자별 게시물 조회
CREATE INDEX idx_posts_user_id ON posts(user_id);

-- 상태별 게시물 조회 (히스토리 필터)
CREATE INDEX idx_posts_status ON posts(status);

-- 예약 시간 조회 (cron job)
CREATE INDEX idx_scheduled_posts_scheduled_at ON scheduled_posts(scheduled_at);
CREATE INDEX idx_scheduled_posts_status ON scheduled_posts(status);
```

## 5. 주요 쿼리 예시

### 예약된 게시물 조회 (cron job용)
```sql
SELECT sp.*, p.*, ia.access_token
FROM scheduled_posts sp
JOIN posts p ON sp.post_id = p.id
JOIN instagram_accounts ia ON p.instagram_account_id = ia.id
WHERE sp.status = 'pending'
  AND sp.scheduled_at <= NOW()
  AND sp.retry_count < 3
ORDER BY sp.scheduled_at ASC;
```

### 사용자 히스토리 조회
```sql
SELECT p.*, sp.scheduled_at
FROM posts p
LEFT JOIN scheduled_posts sp ON p.id = sp.post_id
WHERE p.user_id = ?
ORDER BY p.created_at DESC
LIMIT 20;
```
