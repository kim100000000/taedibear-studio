## 🔴 버그
- [x] **리뷰 댓글 username "@?" 표시** — `ReviewsPage`가 `@{comment.username || '?'}` 렌더. Meta가 username을 안 주는 경우(권한 재연동 전, 비공개 계정) null. 재연동 후에도 재현되면 개별 댓글 조회로 보강. '?' 대신 "(알 수 없음)" 등 안내 문구로 개선
  - ✅ 완료(07-09): '@?' → '(알 수 없는 사용자)' 문구로 개선 (근본 원인은 재연동 후 재확인)
- [x] **삭제된 댓글이 리뷰 목록에 잔존** — `ReviewService.syncComments`가 추가만 하고 삭제 동기화 없음. 동기화 시 Meta 응답에 없는 comment_id는 deleted 처리(또는 행 삭제)
  - ✅ 완료(07-09): 동기화 시 Meta 응답에 없는 댓글 삭제 (조회 실패 게시물은 오삭제 방지 위해 건너뜀)

- [ ] **릴스 자동 생성** — 사진 여러 장 → 템플릿 슬라이드쇼 영상(서버 ffmpeg, 텍스트 오버레이) → Meta API REELS 발행. 크레딧 3~5개 소모. Pro도 릴스는 크레딧 소모(또는 월 N회 포함) → Business 상위 플랜의 차별화 근거 (docs/10 4-4절 연계)
- [ ] **커뮤니티 탭** — 초기엔 보류 (빈 커뮤니티는 역효과 + 관리 부담). 유저 확보 후 오픈카톡/네이버카페로 시작 → 검증되면 인앱 탭
- [ ] **연락처 관리 + DM 일괄 발송** (07-09) — ⚠️ **Meta 정책 리스크 큼**: Instagram Messaging API는 사용자가 먼저 보낸 DM에 24시간 내 응답하는 구조만 허용. 불특정 다수에게 홍보 DM 일괄 발송은 정책 위반으로 계정 제재 위험 → 그대로는 구현 불가. 정책에 맞는 대안: (1) 신제품 소식은 게시물/스토리 발행으로(이미 핵심 기능), (2) 먼저 DM 준 고객 목록 관리 + 24시간 창 내 답장 보조, (3) 댓글 단 고객에게 답글로 안내. 착수 전 최신 Messaging API 정책 재확인 필수

## 확인된 사항 (구현 불필요)
- **Pro 구독 시 사용량 표시**: 이미 처리됨 — Pro는 `limit=null`이라 "3 / 10" 대신 "3"(이번 달 업로드 수)만 표시, Free 배지·경고색도 사라짐
- **캡션은 매번 다르게 생성**: 사진+업종/분위기 기반이며 같은 사진도 재생성마다 다름 (의도된 동작)
- **조회수 0 원인**: (1) `instagram_manage_insights` 권한 추가 후 계정 재연동 전이라 인사이트가 안 들어옴, (2) Meta 인사이트는 발행 직후 집계 지연, (3) 새 계정·팔로워 0이면 실제 조회 0이 정상 — 캡션 문제로 단정할 수 없음
- **AI의 이미지 처리 방식** (07-09 확인): 업로드 이미지는 S3 저장 → 캡션 생성 시 서버가 S3에서 내려받아 base64로 인코딩해 Gemini에 이미지+프롬프트(업종/분위기)로 전달 → Gemini가 이미지를 직접 보고 캡션 생성. 현재는 **1장만** 전달 (다중 이미지는 🟡 백로그 참고)
- **동시 처리 방식** (07-09 확인): API 요청은 Tomcat 스레드 풀(기본 200)로 병렬 처리 — 여러 사용자가 동시에 캡션 생성해도 각자 스레드에서 독립 처리. 크레딧 차감은 DB 원자적 UPDATE(`credits > 0` 조건 포함)라 동시 요청에도 음수 불가. 이메일 발송은 `@Async` 별도 스레드. 단, `@Scheduled` 잡 4개는 기본 단일 스레드 공유 — 🟠 백로그(스레드 풀 설정) 참고
