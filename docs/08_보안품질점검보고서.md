## 🔴 Critical — 즉시 수정 권장

### C1. 결제 금액 서버 검증 없음 (`PaymentService.confirm`)
클라이언트가 보낸 `amount`를 그대로 토스 승인 API에 전달하고 Pro로 업그레이드함. 주문 생성도 클라이언트에서 하므로, 100원짜리 결제를 만들어 승인받아도 Pro가 됨.
- **수정**: 서버에 플랜 가격 상수를 두고 `request.amount()`와 대조. 불일치 시 거부. 토스 공식 가이드도 승인 전 서버측 금액 검증을 필수로 안내함.

### C2. 토스 키 미설정 시 결제 승인 스킵 후 Pro 부여
`tossSecretKey`가 비어 있으면 승인 API를 건너뛰고 그대로 `plan=pro` 저장. 운영에서 환경변수가 빠지면 전원 무료 Pro.
- **수정**: 개발 모드 스킵은 별도 프로파일(`@Profile("dev")`) 또는 명시적 플래그로만 허용하고, 운영에서 키가 없으면 부팅 실패시키기.

### C3. CORS 전체 오픈 (`SecurityConfig`)
`allowedOriginPatterns("*")` + `allowCredentials(true)` → 어떤 사이트든 사용자의 요청을 위조 가능.
- **수정**: `configuration.setAllowedOrigins(List.of(clientUrl))` 로 제한.

### C4. refresh가 만료된 토큰을 무기한 허용 (`AuthService.refresh`)
만료 무시 + 서명만 검증이므로 한 번 탈취된 토큰은 영원히 새 토큰으로 교환 가능. 사실상 만료 없는 토큰.
- **수정**: 별도의 refresh token(DB 저장, 회전, 폐기 가능) 도입. 최소한 만료 후 유예기간(예: 7일)을 두고 그 이후는 거부.

### C5. OAuth `state` 생성만 하고 검증 안 함 (`AuthController`)
구글/카카오 콜백은 state를 아예 확인하지 않고, 네이버도 저장된 값과 대조하지 않음 → OAuth CSRF(공격자 계정을 피해자 브라우저에 연결).
- **수정**: state를 세션/단기 캐시에 저장 후 콜백에서 대조.

### C6. JWT가 URL 쿼리로 노출
`/auth?token=...`(소셜 로그인), `/api/instagram/connect?token=...`, Meta `state`에 JWT 전달. URL은 브라우저 히스토리·서버 로그·프록시에 남음.
- **수정**: 소셜 로그인은 일회용 인증 코드(짧은 TTL, 1회 교환)로 전달하고 프론트가 코드→토큰 교환. Instagram 연동 state에는 JWT 대신 랜덤 nonce를 DB에 저장해 매핑.

### C7. SSRF (`GeminiService.downloadImage`)
`image_url`을 검증 없이 서버가 다운로드 → 내부망/메타데이터 endpoint(169.254.169.254 등) 접근 가능.
- **수정**: 자사 S3 버킷 도메인 prefix만 허용하는 화이트리스트 검증.

### C8. JWT secret 기본값
`${JWT_SECRET:change_this_secret}` — 18바이트라 jjwt(HS256 최소 32바이트) 기준 부팅 시 WeakKeyException으로 실패할 가능성이 높지만, 기본값 존재 자체가 위험.
- **수정**: 기본값 제거(미설정 시 부팅 실패), 32바이트 이상 강제.

## 🟠 High — 로직 우회/악용 가능

### H1. 크레딧 관련 race condition
`deductCreditForCaption`, `watchAd`, `checkPlanLimit` 모두 읽기→검사→쓰기 패턴. 동시 요청으로 잔여 크레딧 1개로 캡션 N회 생성, 광고충전 하루 2회 제한 우회 가능.
- **수정**: `@Lock(PESSIMISTIC_WRITE)` 조회 또는 `UPDATE users SET credits = credits - 1 WHERE id=? AND credits > 0` 식 원자적 쿼리.

### H2. 온보딩 보너스 무한 반복 (`UserService.completeOnboarding`)
주석에는 "1회만"이지만 가드가 없음 → `/onboarding-complete` 반복 호출로 크레딧 무한 충전.
- **수정**: `onboarding_completed` 컬럼 추가 후 체크.

### H3. 광고 시청 검증 없음 (`/credits/ad-watch`)
클라이언트가 그냥 POST만 하면 크레딧 지급. 광고 SDK의 서버 사이드 검증(SSV) 콜백으로 지급하도록 변경 필요. (하루 2회 제한이 있어 피해는 제한적)

### H4. 크레딧 차감 후 Gemini 실패 시 미환불 (`PostController.generateCaption`)
차감 → Gemini 호출 순서라 AI 실패 시 크레딧만 소모됨.
- **수정**: 성공 후 차감하거나, 실패 시 보상 트랜잭션으로 환불.

### H5. Pro 만료 미집행
`validUntil` 30일을 저장만 하고 아무도 확인하지 않음 → 1회 결제로 영구 Pro.
- **수정**: 일일 스케줄러로 만료된 Pro를 free로 다운그레이드하거나, `checkPlanLimit`/`getStatus`에서 `validUntil` 검사. 장기적으로는 빌링키 정기결제.

### H6. Rate limiting 없음
Node 버전에는 `express-rate-limit`이 있었지만 Java 포팅에서 빠짐. 로그인 brute force, Gemini API 남용(비용), 회원가입 스팸에 노출.
- **수정**: Bucket4j 필터로 `/api/auth/login`(IP당 분당 5회), `/api/posts/caption`(사용자당 분당 제한) 등 적용.

### H7. Instagram access token 평문 저장
DB 유출 시 사용자 계정으로 직접 게시 가능.
- **수정**: AES-GCM 등으로 컬럼 암호화(키는 환경변수).

### H8. 업로드 검증이 클라이언트 Content-Type 신뢰 (`S3Service`)
확장자/매직바이트 검증 없음. 또한 S3 객체가 public URL로 노출되는 구조.
- **수정**: 매직바이트 검사 추가, 장기적으로 presigned URL 검토.

## 💡 추가 기능 제안

**수익 관점 (우선순위 높음)**
1. **빌링키 정기결제** — 현재는 1회 결제 + 만료 미집행(H5). 토스 빌링으로 자동 갱신해야 구독 모델이 성립함.
2. **비밀번호 재설정 / 이메일 인증** — EmailService가 이미 있어 구현 비용 낮음. 현재는 비밀번호를 잊으면 복구 불가.
3. **결제 실패/만료 임박 이메일 알림** — 이탈 방지.

**제품 관점**
4. **다중 이미지(캐러셀)·릴스 업로드** — Meta API가 지원하며 소상공인 수요 큼.
5. **콘텐츠 캘린더 뷰** — 예약 목록을 달력으로. 예약 기능의 체감 가치를 크게 올림.
6. **캡션 재생성/톤 조절** — 생성 결과가 마음에 안 들 때 크레딧 절반 또는 무료 1회 재생성.
7. **Meta 인사이트 연동 실제 성과 분석** — 현재 analytics는 자체 DB(업로드 수)만. 도달/좋아요/댓글이 진짜 가치.
8. **최적 업로드 시간 추천** — 인사이트 데이터 기반, AI 서비스라는 정체성과 맞음.

**운영 관점**
9. **관리자 role** — 현재 role 개념이 없음. 사용자/결제 관리 화면 필요 시점이 곧 옴.
10. **Flyway + 테스트 + CI** — M7/M10. 결제가 붙은 서비스는 스키마와 회귀 안정성이 필수.
11. **Sentry 등 에러 모니터링 + Spring Actuator health** — 현재 `/health` 수동 구현.
